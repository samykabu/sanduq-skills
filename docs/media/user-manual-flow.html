Writing and keeping a user manual

A new manual starts with an interview and a look at the repository, then a proposed module map that you approve, with as many rounds of changes as you need, before init_manual.py creates User-Manual/. An existing manual starts from manual.yml and the relevant diff. Both write or update only the affected pages, with diagrams from illustrate when it is installed. audit_manual.py must pass before build_manual.py renders the editions with the configured renderer: Markdown, your own command, or MkDocs. manual_state.py records freshness, and its status exits 1 once code changes, which sends you back to update the manual.
